# Macedonian Learning Repository Instructions

These instructions apply to every Macedonian lesson run from this repository.

## Source of truth

The repository files are authoritative:

- `macedonian_lesson_structure.md` — how lessons are delivered
- `macedonian_syllabus.md` — flexible competency sequence and prerequisites
- `macedonian_vocabulary.md` — current vocabulary evidence
- `macedonian_grammar.md` — current grammar evidence

Do not substitute conversational memory for these files. Conversation history may be used only as evidence that must be reconciled into the trackers.

## Before every lesson

1. Read all four authoritative Markdown files in full.
2. Compare the latest completed lesson evidence with the reconciliation markers in both trackers.
3. If evidence is newer, missing, or inconsistent, update both trackers before teaching.
4. Re-read the updated sections and verify that both reconciliation markers agree.
5. Use the trackers to locate the learner in `macedonian_syllabus.md`; the trackers, not a fixed schedule, determine the next lesson.
6. Follow the lesson order and one-prompt-at-a-time interaction defined in `macedonian_lesson_structure.md`.

## During every lesson

- Use English for explanations and Macedonian Cyrillic as the target language.
- Include Latin transliteration for genuinely new Macedonian material.
- Never assume that `encountered` means learned or independently retrievable.
- Do not use an item marked `unverified` as prior knowledge.
- Introduce at least two genuinely new base words.
- Keep an explicit internal phase checklist and do not skip, duplicate, or mislabel phases.
- Validate every response against both the target prompt and correct Macedonian before grading it.
- End with the required short conversation.

## After every completed lesson

1. Give the learner a concise recap of new material, successes, corrections, and next retrieval priorities.
2. Update both vocabulary and grammar trackers with dated, factual evidence.
3. Record learner errors, teaching corrections, independent successes, new material, and future retrieval priorities.
4. Set both `Last completed lesson reconciled` and `Last reconciliation performed` markers to the completed lesson date.
5. Record a cumulative-review date when applicable.
6. Re-read and verify both files before claiming that progress was saved.
7. Commit the tracker changes to Git with a concise dated commit message.

Never claim that a file was updated or progress was saved unless the write and verification succeeded.
